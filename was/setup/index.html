Setting up the weapon

Guide for configuring the Weaponry Assembly System (WAS) in Unreal Engine.

Check the requirements

First of all, make sure you have the Weaponry Assembly System (WAS) plugin installed and enabled in your project. Also make sure Gameplay Tags are enabled, and that Niagara is active in your project settings.

Create the gameplay tags

You will need to define the slots and modifications for each weapon. The recommended way to do this is by editing: Config/DefaultGameplayTags.ini

Structure reference:

  • Weapon
    • Weapon.Slot0
      • Weapon.Slot0.Modification0
      • Weapon.Slot0.Modification1
      • Weapon.Slot0.Modification2
    • Weapon.Slot1
      • Weapon.Slot1.Modification0
      • Weapon.Slot1.Modification1
      • Weapon.Slot1.Modification2
    • Weapon.Slot2
      • Weapon.Slot2.Modification0
      • Weapon.Slot2.Modification1
      • Weapon.Slot2.Modification2

A slot's children must always represent modifications. You can use DevComments to annotate metadata, which we will use later on.

Create the weapon characteristics

This is a data container class, not the weapon itself. It behaves like a data asset that stores the weapon's configurable parameters.

Create a Blueprint derived from UWeaponDefaultCharacteristics and add variables such as fire rate, magazine size, recoil, and so on. For now, create at least a fire-rate variable of type float. Override GetTriggerRate and connect that variable directly to the return value. Also override GetTriggerMode and make it return Automatic.

On top of that, override GetUsesAmmo and GetUsesMagazine and make both return false, so you won't need ammo for your first tests.

To override these functions, use the Override dropdown in the Blueprint editor and map them to your variables.

Create the weapon asset

Right-click in the folder where you want to create the asset, go to Create Advanced Asset, select Weapon Asset, give it a name, and open it.

Inside, you will find an editor graph, a preview window, and a properties panel.

First, go to the properties panel and, under Characteristics, switch it to the one you created in the previous step. As soon as you do, all your properties will become editable. For now we'll focus on expanding the Modification section. You will see a Weapon Root variable and a Container one. Replace Weapon Root with this weapon's root tag, meaning the tag that contains all the slots. You may need to close and reopen the asset for the changes to take effect. After that, you'll get a list of options for every slot you created, each one with its own modification options.

Next, to actually build the weapon, you need to create an end node: right-click on the graph and add a Build Visuals node. This node is meant to run when you only want to build the visual side of the weapon, leaving properties untouched. Let's create a static mesh component using the Weapon Static Mesh node, under the Spawn category. For the input Asset pin, we'll use a Literal Object node. By default it can be any object, but as soon as you connect it to a pin that requires a specific type, it will automatically filter to acceptable types only — in this case, the Object node will become a StaticMesh. From there, in the node's details, you can set the mesh you want to spawn.

Let's continue with the basics by adding attachments. In a very similar way to how we created this single static mesh, create another static mesh component, but this time the input Asset will be Select Object By Mod. Connect it to the input and go to its details. You will see a Slot field set to None. Change it to whichever slot you want. An options map will then be generated automatically with every possible modification — just select the mesh you want to spawn for each modifier. From the output pin of the generated static mesh, it's a good idea to assign it a tag, which you can do by creating a new Tag node. Give it whatever tag you like, since this is just to help identify the component later on. Next, create a Weapon Attachment node, where the parent is whoever will hold the components, and the children are the ones attached to it. You can repeat the process by chaining the Result output into the parent of the next Weapon Attachment. Remember to connect the end of the chain to the Build Visuals node.

Now let's make our fire rate changeable so we can test it later. Add a new Execute Operations node — this node will run anything connected to it, but it's meant to be used purely to modify properties, so let's use it for that. Create a new node for the fire-rate property (the one we created earlier in the characteristics) and use a SelectDoubleByMod node (or Float), connecting it to the fire rate's input. Just like we did with the components, select a slot and give a value for each modifier.

Create your weapon component

Let's start testing this out with a simple new Blueprint derived from UWeaponComponent. I'll keep this short since it's a bit off-topic. You'll see there are many different functions you can override. Override OnEventTriggered and print the string Shooting works!!!. Then do the same with OnEventTriggerFailed and print Could not shoot :(.

That's all for now on our UWeaponComponent. Let's move on to our character.

Create your character

Create a new ACharacter (or use the one you most likely already have) and add a new component of the type we just created. In the component's details panel, look for Weapon Asset and select the Weapon Asset we created.

Next, let's add a simple input event, OnLeftMouseButton: when pressed, we'll call EnterTrigger on our WeaponComponent, and when we release the left click, we'll call ExitTrigger.

Test it!

As soon as your character appears, you should be able to see your weapon already built. If you can't, make sure it's visible, the attachment is set up correctly, and that it isn't underground or in some other unexpected location. Also double-check that you've set the Weapon Asset.

You should now be able to shoot, and the message should print to screen. Shooting will be continuous if the trigger mode is set to Automatic, and as soon as you release the click, the trigger will be released and shooting will stop.

If something goes wrong and the game keeps printing "Could not shoot :(", you very likely have no ammo. You can override GetUsesAmmo and GetUsesMagazine on your UWeaponCharacteristics and make both return false.

Indicate all information in data assets

Now let's fill in the information for the slots and modifiers. If you haven't set a DevComment for each slot and modifier yet, I'd recommend doing so now — even with AI, since it will give you an output you can use as a starting placeholder. This depends on your project, but a good recommendation is to create two Primary Data Assets: one called PDA_WeaponDescription and another called PDA_WeaponLibrary.

PDA_WeaponDescription: this Primary Data Asset consists of a single variable of type Weapon Settings Description Simple. Save it and create a DataAsset from it — this is just a DataAsset for a single weapon. Open it up and, where you see RootTag, give it your weapon's root tag, the same one you assigned on the Weapon Asset. As soon as you set that value, it will automatically populate with all the slots and modifiers, and if you filled in the DevComments, the description will be populated automatically too.

PDA_WeaponLibrary is the second Primary Data Asset, and it will act as a library holding the information for every weapon asset. Open it up and create a new Map variable, using WeaponAsset as the key and PDA_WeaponDescription as the value. I'd recommend using a soft reference for both the key and the value. Create a new DataAsset from it and add an entry: the Weapon Asset we're working on and the Weapon Description we just created.

Display and modify the weapon in game

Now let's add the ability to modify the weapon at runtime. Go back to your character and create an event to display the modification widget — for example, on pressing the "C" key.

Add a new variable called library, of type PDA_LibraryWeapon, and set it to the library data asset we created earlier. Now, when we enter the event to display the widget, we'll first get the WeaponComponent from our character, and from it, GetWeaponAsset. From the Library variable we'll get the Map property and use Find. The input for that Find will be the result of GetWeaponAsset. If we're using a soft reference, we'll need to load it; once loaded, the resulting object will be a PDA_WeaponDescription, since that's the value type of the map. You may need to use a cast, and from there just get the description variable.

Now we have all the information the widget needs, so just call CreateWidget, where the class should be WBP_ModifyWeapon. That's the built-in implementation, and its input pins will be WeaponToModify (our character's weapon component), Weapon Asset (the weapon component's weapon asset), and finally the Weapon Settings Description Simple, which will be the value we got from the Primary Data Asset.

As for the return value, you can bind Apply Mods to a function that closes the widget, so that function gets called automatically whenever the modifiers are applied. From there, treat it like a regular widget: add it to the screen, show the mouse cursor, set the input mode to UI, and so on.

Add more variability

Now that everything is set up, you can start adding more modifiers, more static meshes, more variables, and so on.

Test it (again)!

If your fire rate is driven by a variable, you'll be able to see how it changes with each modifier.
