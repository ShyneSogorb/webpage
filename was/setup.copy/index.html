Setting up the weapon

Guide for configuring the Weaponry Assembly System (WAS) in Unreal Engine.

Ensure requirements

First of all, make sure you have the plugin installed and active in your project Weaponry Assembly System (WAS). Also ensure Gameplay Tags are enabled, and Niagara Particle System is active in your project settings.

Create the gameplay tags

You will need to define slots and modifications per weapon. The recommended approach is editing: Config/DefaultGameplayTags.ini

Structure reference:

  • Weapon
    • Weapon.Slot0
      • Weapon.Slot0.Modification0
      • Weapon.Slot0.Modification1
      • Weapon.Slot0.Modification2
    • Weapon.Slot1
      • Weapon.Slot1.Modification0
      • Weapon.Slot1.Modification1
      • Weapon.Slot1.Modification2
    • Weapon.Slot2
      • Weapon.Slot2.Modification0
      • Weapon.Slot2.Modification1
      • Weapon.Slot2.Modification2

Slot children must always represent modifications. DevComments can be used to annotate metadata later.

Create weapon characteristics

This is a data container class, not the weapon itself. It behaves like a data asset storing configurable parameters.

Create a Blueprint derived from UWeaponDefaultCharacteristics. Add variables like fire rate, magazine size, recoil, etc. For now lets create at least a fire-rate variable which will be floating point. Override the GetTriggerRate and just connect the variable to the return value. Now also override GetTriggerMode and return automatic.

Also you should override the GetUsesAmmo and GetUsesMagazine and make both return false so you dont need ammo in order to test it

Override required functions using the Override dropdown in the Blueprint editor and map them to your variables.

Create the weapon asset

Right-click wherever you want to create your asset. Then go to Weapon Asset in create advanced asset and select Weapon Asset give it a name and open it

Here you will find a editor graphp, preview window and properties.

First of all you should go to properties and at characteristics change it to the one you created on previous step. Once you have change it all your properties must appear as editable. For now we will continue expanding the Modification section. You will see a Weapon Root variable and Container. Change Weapon Root with the root of this weapon's tag Meaning, the tag that contains all the slots. Now you may have to close and open the asset again in order for the changes to take place. And now you will have a list of options with all the slots you created, each one with their own modifications options

Next, in order to build the weapon you have to create an end node, right-click on the graph and use a build visuals. This node is intended to be executed when you only want to build up the visuals aspects of the weapon, leaving properties unchanged. Lets create a static mesh component in this case with the node Weapon Static Mesh under the Spawn category. And on the input asset, we will use Literal Object. By default it can be any object, but once you have connected it with a pin that requires a specific type it will filter by acceptable types only, so when you connect it the Object node will become StaticMesh. And there, on the details you can set your mesh to spawn.

We will continue with the basis, adding the attachments. In a very similar way that we have created this sole static mesh, first create another static mesh component, and this time the input asset will be Select Object By Mod. Connect it to the input and go to the details. You will see Slot set to None. Change it to whichever slot you desire. Then the options map will be generated with all the possible modification Just select the mesh you want to spawn for each modificator. From the outpin of the generated static mesh would be a good idea to assign it a tag. In order to do so just create a new Tag node. Give the tag that you wish since this is just to help identifying the component later. Next create a Weapon Attachment, where the parent is who will hold the components, and the children the attached. You can repeat the process concatenating the Result output with the parent of the next Weapon Attachment. Remember to connect the end to the build visuals node.

Now lets change our fire-rate so we can test it out later. Add a new node called Execute Operations, this will execute anything connected to it, but is intended to be used just to modify properties, so lets do that. Create a new node, fire-rate, which is the one we created previously in the characteristics. And use a SelectDoubleByMod(or float), and connect it to the input of the fire-rate. Just like we did with the components, select a slot, and give values for each modificator

Create your weapon component

Lets start testing out with a simple new blueprint derived from UWeaponComponentI will keep it short since this is slightly off-topic. You will see that there are a lot of different functions that can be overriden, lets override OnEventTriggered. And print string Shooting works!!!. Then repeat with OnEventTriggerFailed and now print Could not shot :(.

This is all at the moment from our UWeaponComponent, lets go now to our character

Create your character

Create a new ACharacter (or use the one that you, very likely, already have), and add a new component of the type we just created. On the details panel of the component look for Weapon Asset, and there, select the Weapon Asset we created.

Next lets add a simple input event, OnLeftMouseButton, when pressed we will call EnterTrigger from our WeaponComponent And when we release the left click, we call ExitTrigger

Test it!

As soon as your character appears, you should be able to see your weapon built. In case you don't, make sure it is visible, the attachment is correctly set, not undergrown or any other random location. Also make sure you have set the weapon Weapon Asset

Now you should be able to shot. And the message should be printing on screen. The shooting should be continuous if the trigger mode is set to automatic, and as soon as you release the click, will release the trigger and stopped shooting

In case something goes wrong. And just keeps telling you that "Could not shot :(" Very likely you have no ammo, you could override the GetUsesAmmo and GetUsesMagazine and make both return false in the UWeaponCharacteristics

Indicate all information in data assets

Now lets continue by filling information for the slots and modifiers. In case you have not set DevComment to each slot and modificator I recommend you to do so. Even with AI, since will give you an output that you can use as placeholder. This depends on your project, but a recomendation would be to create two Primary Data Assets. One will be called PDA_WeaponDescription and the other PDA_WeaponLibrary.

PDA_WeaponDescription This Primary Data Asset consist on just a single variable of type Weapon Settings Description Simple. Save and create a DataAsset from it, this is just a DataAsset for a single weapon. So open it up, and where you read RootTag, give it the tag root of yout weapon, just the same we gave at the WeaponAsset. Once you give it the value, will populate with all slots and modificators automatically, if you filled the comment dev then also the description will be filled automatically

PDA_WeaponLibrary is the second primary data asset and will serve as a library with the information of all weapon assets. So open it up and create a new map container variable of type WeaponAsset as key and PDA_WeaponDescription as value. I recommend using a soft reference for both Key and Value. Create a new DataAsset from it and give a new input, the WeaponAsset we are working on and the Weapon Description we just created.

Display and modify weapon in game

Now lets add the ability to modify the weapon in runtime. So, for that, go back to your character, and create an event to display the modification for example letter "c".

Add a new variable and call it library, make it PDA_LibraryWeapon and give it the value of that library data asset we made previously. Now, when we enter the event to display the widget, first will get the WeaponComponent from our character, and from it, GetWeaponAsset. From the Library variable we will get the map property and use find. The the find input will be the GetWeaponAsset. From it, if we are using a soft reference we must load it, when it loads, the object resultant will be a PDA_WeaponDescription since that's the value of the map. You may need to use a cast for it, and from there just get the variable description

Now we have all information that the widget needs, so just CreateWidget, where class should be WBP Modify Weapon. That is the built in implementation, and the input pins will be WeaponToModify, the weapon component of our character. Weapon Asset will be the weapon asset of the weapon component, and finally the Weapon Settings Description Simple, will be the value received from the Primary Data Asset.

Now the return value, you can bind Apply Mods to a close widget function, so when you apply the modificators the that function gets called automatically. From there treat it as a regular widget, add it to screen, show mouse cursor, set gameplay mode to UI, etc.

Add more variability

Now with everithing setted up. You can start adding more modifiers, more static meshes, more variables, etc.

Test it (again)!

If your fire-rate is based on a variable, you can see how the fire-rate changes with the mod.
